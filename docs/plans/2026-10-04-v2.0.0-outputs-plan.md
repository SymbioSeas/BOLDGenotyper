## Phase 10: Query outputs and overlays

Design §3. A query run folder gets files named for their use, a README with a methods
sentence, provenance as JSON, an HTML report, and figures that place the queries in the
reference run. Two choices made here, for review:

- The writers go in a new `boldgenotyper/query_outputs.py` rather than growing
  `haplotype_query.py` (1,017 lines); `haplotype_query.py` keeps alignment and the query
  loop.
- Figures are written for every v2 run-folder reference, each when the reference has what
  it needs (a tree, regions, dates, mapped records); `--query-metadata` adds the queries'
  own locations, regions and dates. The design gated all figures on `--query-metadata`,
  but placing queries on the tree needs no metadata, and the matched haplotypes' maps,
  regions and dates are useful without it.

Figure pages follow the paging pattern Phase 11 will generalize: a multi-page PDF
(`query_figures/<name>.pdf`) and one SVG per page (`query_figures/<name>/<page>.svg`),
with `svg.fonttype = "none"` so labels stay text. Figure failures are logged and listed
in `query_provenance.json` (`warnings`); the query still exits 0.

### File structure

| File | Responsibility |
|---|---|
| `boldgenotyper/query_outputs.py` (new) | calls and candidates tables, `query_alignments.txt`, `query_results.json` (`--json`), `query_provenance.json`, the query README and its methods sentence |
| `boldgenotyper/query_overlays.py` (new) | the reference run's tables, query metadata, query regions, `query_regions.csv`, tree / map / regions / timeline figures |
