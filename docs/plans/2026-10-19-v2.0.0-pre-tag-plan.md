# BOLDGenotyper 2.0.0: pre-tag changes

**Status (2026-10-19): done; reviewed by Steph 19 Oct.** Tasks 1–9 committed
(6a794a3..729ce67), plus a fix found before the tag (7e862b4).

**Checks.**
- Full suite: 528 passed, 5 skipped, 0 failed (483 before).
- Sphinx builds without warnings; every changed file parses under Python 3.9.

**Simulation of the error filter** (known haplotypes; 3 scenarios × 5 replicates × 16
thresholds):
- The sweep's elbow (0.010) removes simulated errors and puts 98–99.5% of records on their true
  haplotype, while merging rare real haplotypes within about 1% of a common one (7–15% of true
  haplotypes).
- In a study that deposits one sequence per haplotype, the filter kept 16% of true haplotypes
  at the elbow. With the A4b change it keeps 99.6%.
- Species are lost only above the elbow, and `label_in_retained` flags each one.

**Scratch runs on real datasets.**
- A file with a malformed block (10,000 rows with 98 fields instead of 95) stops with the line
  number; with `--allow-malformed-rows` the rows are counted.
- `label_variants.csv` lists misspellings and gender endings (e.g. *Leptidea sinapis*/*sinapsis*,
  *Colias crocea*/*croceus*, *Holothuria poli*/*polii*) alongside valid species two letters apart.
- A spiny-lobster dataset has 5 haplotype-only GenBank studies (141 singletons kept).
- An order-level shark dataset regains 18 specimens whose COI row had been dropped. Its 564 rows
  of other markers are now counted as such, not as duplicates. 4 haplotype-only studies keep 50
  singletons (483 → 524 haplotypes); haplotypes of unaffected genera keep their membership.

## Tasks

1. **Read every TSV row or say why not; select the marker before duplicates (A1, A2).**
   `parse_bold_tsv` reads with `QUOTE_NONE`, counts rows whose field count differs from the
   header's and stops with a clear message (or drops them with `allow_malformed_rows`), keeps
   only rows of the target marker (default `COI-5P`) before removing duplicate processids,
   and reports each count.
2. **Carry the counts and the `--marker` / `--allow-malformed-rows` flags** through the
   pipeline, the sweep, `summary.csv` and `run_provenance.json`.
3. **Clean label formatting and list likely spelling variants (A3):** `label_variants.csv`;
   nothing is merged automatically.
4. **Apply a user-confirmed label map (A3):** `--label-map FILE`, applied before labels are
   pooled, recorded by md5; records.csv `label_mapped_from`.
5. **Suggest a label map from a taxonomic backbone (A3):** `boldgenotyper-labels suggest`
   (GBIF or WoRMS), outside the pipeline run.
6. **Error-filter diagnostics (A4):** `sources.csv` (sources that deposit one sequence per
   haplotype), records.csv `label_in_retained`, summary counts and warnings.
7. **Simulation of the error filter** with known haplotypes (outside this repo), and a
   decision on whether the filter changes.
8. **Filter change (A4b)**, only if the simulation supports one and it is approved.
9. **Docs and verification:** README, CHANGELOG, migration guide, API reference, Sphinx;
   full suite; scratch runs on real datasets.

## Review focus

1. A TSV without a `marker_code` column: marker selection is skipped; no rows are dropped.
2. A specimen whose only rows are another marker: counted (`n_other_marker_rows`) and
   reported, never silently lost.
3. A label map with a chain, a self-mapping or a repeated `from`: loading fails with a
   message naming the rows; nothing is applied partially.
4. Label-map entries and labels that differ only in formatting: both pass through the same
   cleanup, so the map still matches.
5. The backbone helper offline or timing out: a clear message and no partial file.
