# BOLDGenotyper v2.0.0: Outputs, Report, Query and Taxon Curation (Design)

Date: 2026-10-04
Status: approved 2026-10-04; Phases 8 and 9 done; Phase 9 review decisions applied, awaiting review
Branch: `release/v2.0.0` (not pushed; these changes go into 2.0.0)
Follows: `2026-09-30-v2.0.0-release-design.md` (Phases 0–7)

## Context

A review of 2.0.0 outputs on two real datasets, run with `--build-tree --extended`:
an order-level dataset (8,673 QC-passed records, 483 haplotypes, 167 species-level taxa,
8 ocean basins, 81 countries) and a genus-level dataset (593 QC-passed records, 34
haplotypes, 7 species), plus a parameter sweep and a haplotype query against the
genus-level run.

What works: the run tables, the run README, provenance, the sweep, and the figures of the
small dataset. What does not:

1. **Methods tab.** Every count reads "not recorded" and the tree is reported as not
   built. The report is generated (`cli.py` Phase 13) before the full provenance is
   written (end of `run_pipeline`), so it reads the provisional file written at startup.
2. **Large datasets.** Every haplotype-level figure draws all haplotypes on one fixed
   canvas: 461 tree tips on one page, legends of about 400 entries, haplotype-faceted maps
   of 5–30 MB. The largest species has 23 haplotypes, so organizing figures by species
   keeps every page legible.
3. **Report content.** It restates long tables that are already files (taxonomy, a v1
   "species composition of consensus groups" table, haplotype × region, field coverage,
   first-sampled dates), says "Showing first N rows of N total" because it counts the
   truncated table, and describes records without a region as "unknown ... excluded".
4. **Metadata.** Figures are PNGs capped at 150 dpi, so large ones are blurry. The default
   fields include BOLD's coordinate-derived terrestrial `realm`, `biome` and `ecoregion`
   (marine records land in deserts and forests), the numeric `geoid` code and
   `country_iso`, a copy of `country/ocean`.
5. **Query outputs.** Six files with no README; users cannot tell which one is the result.
   Query samples cannot be shown with the reference run's map, regions, timeline or tree.
6. **Haplotype taxa.** `assigned_sp` uses member labels only. A haplotype whose eight
   members are labeled 4/4 between two congeners (four labels from one project with no
   BIN, four from three institutions sharing a BIN) gets the genus, although it lies within
   the observed spread of one species and far from the other; every query matching it
   inherits the genus-level call.
7. **Smaller issues.** `divergence/pairwise_p_distance.csv` is keyed by display labels,
   which change when a taxon changes; the sweep README says per-threshold tables are kept
   only with `--keep-intermediates` (they are always kept); 12 tests fail (stale fixtures
   and expectations; one in an unused module); deprecated v1 flags and functions remain.

## Goals

- Every figure legible at any dataset size; every page usable as a publication panel.
- The report as the central, accurate guide to a run: what was done, what was found, what
  needs attention, and which file holds what. No restated raw tables.
- Query results that are easy to report and easy to show alongside the reference run.
- Haplotype taxa that can be checked against independent evidence and corrected
  explicitly, with the correction recorded and inherited by queries.
- No assumption specific to marine taxa, GOaS or one dataset.

## Non-goals

- Interactive (JavaScript charting) figures; new plotting dependencies.
- Automatic taxon reassignment from distances or the tree.
- Phylogenetic placement of novel query sequences (EPA-ng, pplacer).
- Re-running the full pipeline with local records added.

## Decisions (Steph, 2026-10-04)

| Topic | Decision |
|---|---|
| Large-dataset figures | Species-organized static figures: an overview plus multi-page PDFs with one page per species; the report shows those pages through dropdowns. No new dependency. |
| Query samples with the reference run | Overlays produced by the query run from a query metadata file; the reference run is not modified. Iterate by re-querying all samples against the same reference run. |
| Haplotype taxa | Evidence and a suggested taxon in `haplotypes.csv` and the report, never applied automatically; a curation file records accepted calls and queries inherit them. |
| Deprecated v1 flags and functions | Removed in 2.0.0; a removed flag fails with one line naming its replacement; history stays in the CHANGELOG and migration guide. |
| Test failures | The 12 pre-existing failures are fixed in 2.0.0. |

## Design

### 1. Correctness fixes (Phase 8)

- **Methods tab.** `generate_html_report` takes the in-memory provenance (the dict
  `Provenance.write` serializes) and no longer reads `run_provenance.json`. In Phase 12 the
  report is built last (section 5), which removes the ordering dependency altogether.
  Test: a synthetic run with `--build-tree` and a report has no "not recorded" in the
  Methods tab and states the tree's tip count.
- **Table counts.** `_dataframe_to_html` reports the row count before truncation.
- **Metadata default fields.** `sex`, `life_stage`, `reproduction`, `habitat`,
  `country/ocean`, `province/state`. `realm`, `biome`, `ecoregion`, `geoid` and
  `country_iso` are summarized only when named in `--metadata-fields`; the run README and
  user docs say that BOLD derives `realm`, `biome` and `ecoregion` from coordinates using
  terrestrial ecoregions.
- **Distance matrix keys.** `pairwise_p_distance.csv` rows and columns are `haplotype_id`;
  consumers that need taxa join `haplotypes.csv`. The divergence heatmap keeps display
  labels.
- **Sweep README.** `runs/` keeps each threshold's record and haplotype tables (needed for
  the stability table); `--keep-intermediates` keeps everything.
- **Test failures.**
  - `test_dereplication.py`: import `Mock`.
  - `test_metadata.py` (4 tests): add the missing fixture `tests/data/test_bold.tsv`, a
    small synthetic BOLD-format file with the rows the tests expect.
  - `test_duplicate_processids`: assert the documented behavior (first record kept, a
    warning logged) instead of an error.
  - `test_whitespace_cleanup`: `parse_bold_tsv` strips surrounding whitespace from
    `processid` and `nuc` (code fix).
  - `test_valid_iupac_ambiguous_nucleotides_accepted`: `utils.validate_sequence` accepts
    IUPAC ambiguity codes; only `N` counts toward the ambiguous fraction, as in QC (code
    fix).
  - `test_metadata_summary.py` (2 tests): assert the paths the functions write (updated
    again in Phase 11).
  - `test_below_threshold_unassigned`: tests `haplotype_assignment.find_best_haplotype_match`,
    v1 identity-based assignment that the pipeline imports but never calls. Removed with
    the module (approved).
- **Removals (approved).** CLI flags `--similarity-threshold`, `--tie-margin`,
  `--tie-threshold`, `--no-export-plot-data`, `--no-export-format`,
  `--no-metadata-analysis` and `boldgenotyper-query --tie-margin`; functions
  `quality_control.add_contamination_columns`, `quality_control.detect_depositor_uncertainty`,
  `haplotype_query.classify_match_quality`, `divergence_analysis.analyze_barcoding_gap`.
  A removed flag exits with status 2 and one line, e.g. `--tie-margin was removed in 2.0.0;
  use --max-mismatch-delta (see docs/guides/MIGRATION_v1_to_v2.md)`. `--help`, README and
  API reference stop mentioning them; CHANGELOG ("Removed") and the migration guide keep the
  mapping.
- **Dead code (approved).** `haplotype_assignment.py`
  (1,240 lines; imported, never called), `config.GenotypeAssignmentConfig` (reported as
  `not_applied` in provenance), `visualization.plot_identity_distribution` and
  `plot_identity_by_status` (identity scores no longer exist), and v1 report helpers that
  read files 2.0.0 no longer writes. Each is checked for callers before removal.

### 2. Haplotype taxa: evidence and curation (Phase 9)

The taxon rule itself does not change: species when more than 0.70 of the counted labels
agree, otherwise genus (design doc of 2026-09-30, Phase 4 review).

**Evidence** (`boldgenotyper/taxon_evidence.py`), computed for every haplotype after the
divergence step and written to `haplotypes.csv`:

| Column | Meaning |
|---|---|
| `nearest_species_haplotype`, `nearest_species_taxon`, `nearest_species_distance` | nearest other haplotype assigned at species level, its taxon and p-distance |
| `taxon_max_within_distance` | largest p-distance between haplotypes of `nearest_species_taxon` (empty when it has one haplotype) |
| `within_taxon_spread` | `nearest_species_distance` ≤ `taxon_max_within_distance` |
| `member_bins` | members' BOLD BINs with counts (e.g. `BOLD:AAB3213 4; none 4`) |
| `bin_taxon` | for the members' most common BIN: the majority species-level label among all QC-passed records of the run in that BIN, with its fraction |
| `label_sources` | per label: distinct BOLD projects (processid prefix) and institutions behind it (e.g. `R. a 4 records / 1 project; R. b 4 records / 3 projects`). Records mined from GenBank share a few project codes across many studies, so for them the GenBank accession prefix is counted instead; the README says sources are approximate |
| `tree_sister_taxon`, `tree_sister_support` | when a tree was built: the taxon shared by every species-level haplotype in the smallest clade that contains this haplotype and at least one other, with that clade's support; empty when the clade mixes taxa |
| `suggested_sp`, `suggestion_basis` | for haplotypes not assigned at species level: a taxon on which at least two of the three independent lines agree (nearest species within its spread; BIN taxon; tree sister taxon), and which lines agree; empty, with "evidence disagrees", otherwise |

Suggestions are never applied. The report lists them under "Needs attention" with their
evidence.

**Curation** (`boldgenotyper/taxon_curation.py`), `--taxon-curation FILE` on
`boldgenotyper` and `boldgenotyper-query`:

- File (CSV or TSV): `seq_md5` or `sequence` (one required), `taxon`, `reason`
  (required), `curator`, `date` (optional).
- Matching: by `seq_md5`; otherwise by sequence, exact or containing / contained in the
  haplotype's core sequence (a curation made on one dataset can apply to another dataset's
  different core region). A row must match exactly one haplotype; unmatched or ambiguous
  rows are logged, listed in the report and not applied.
- Effect: `assigned_sp` = `taxon`; `assignment_level` from the taxon's form;
  `assignment_source` = `curated` (otherwise `labels`); `assignment_notes` =
  `curated: <reason> (<curator>, <date>); labels: <majority note>`. Label columns are
  unchanged. For curated haplotypes, `label_conflict` compares each member's label with
  the curated taxon; `label_conflicts.csv` gains `haplotype_taxon` and
  `assignment_source` so these rows can be read.
- Provenance: file path, md5, rows applied, rows not applied.
- Query species calls: when a haplotype in the equivalence set is curated, the call uses the
  haplotypes' taxa (curated, else label rule): one shared species → that species
  (`call_basis` = `haplotype taxa`); otherwise no call (flag `curated_taxa_disagree`).
  When none is curated, the call is unchanged (pooled member labels, `--min-species-support`;
  `call_basis` = `pooled labels`).

### 3. Query outputs and overlays (Phase 10)

**Files** in the query output folder:

| File | Content |
|---|---|
| `README.md` | what each file holds, which to report, and a methods sentence with the run's values |
| `query_calls.csv` | one row per query; **the result to report**: `query_id`, `call_level`, `equivalence_set`, `n_equivalent`, `species_call`, `call_basis`, `species_support`, `pooled_member_labels`, `differences`, `n_mismatches`, `n_gaps`, `identity_pct`, `query_coverage`, `flags`, `n_exact_record_matches`, `reference_run` |
| `query_candidates.csv` | evidence: the top `--top-n` haplotypes per query with alignment numbers and the haplotype's taxon, `assignment_source` and `n_members`; other haplotype columns by joining the reference `haplotypes.csv` |
| `query_record_matches.csv` | with `--search-records` |
| `query_alignments.txt` | human-readable alignments |
| `query_provenance.json` | reference run (provenance md5, path, version, download date), parameters, curation file |
| `query_report.html` | calls table, one evidence card per query (alignment excerpt, candidates, labels), links into the reference run's report |
| `query.log` | log |
| `query_results.json` | only with `--json` |

The CSVs drop the `#` comment header (spreadsheet users cannot open it cleanly); provenance
moves to `query_provenance.json`. Old names (`query_summary.csv`, `query_results.csv`,
`query_results_detailed.txt`) go to the migration guide.

**Overlays**, with `--query-metadata FILE` (CSV/TSV; `query_id` plus any of `lat`/`lon` or
`coord`, `collection_date`, `country/ocean`, `region`), written to `query_figures/`:

- `query_map.pdf/.svg`: the reference run's mapped records by species (overview styling)
  with query points highlighted and labeled; one page per called taxon.
- `query_regions.csv` and a bar figure: records of the matched haplotypes per region in the
  reference run, with the queries added as a separate series.
- `query_timeline.pdf/.svg`: the sampling dates of the matched haplotypes with the query
  dates marked.
- `query_tree.pdf/.svg` (reference run built a tree): the subtree of each called genus with
  each query drawn next to the tip(s) of its equivalence set; queries without an eligible
  match are listed under the figure, not placed.
- A query's region comes from its `region` value; otherwise from its coordinates and the
  reference run's shapefile and field (from the reference provenance), if the shapefile is
  still at that path; otherwise none (logged).

**Iterative use** (docs): keep one reference run per reference dataset; query the full set
of samples to date (a query run takes seconds); every output records the reference run's
provenance md5, so results from different dates are comparable.

### 4. Species-organized figures (Phase 11)

**Rules**

- A figure panel colors at most 12 items. Above 12, the 11 with the most records are
  colored and the rest are drawn in gray as "Other (n)".
- Overviews: up to 40 haplotypes (`visualization.max_overview_haplotypes`), the overview
  is the current haplotype-level figure; above 40 it is species-level (15 species colored,
  "Other species (n)").
- Per-species pages: one page per species-level taxon (and one per genus-level group), in
  a multi-page PDF `<figure>_by_species.pdf`, plus one SVG per page in
  `<folder>/by_species/<figure>/<Genus_species>.svg` for the report. Within a species,
  haplotypes keep the same color on every page.
- Formats: PDF (publication) and SVG (report). Metadata figures move from PNG to PDF/SVG;
  no PNGs are written except by the plot kit.
- Each figure folder gets a `manifest.json` (figure → overview file, per-species files) that
  the report and the run README read.

**Figures**

| Figure | Overview | Pages |
|---|---|---|
| Tree (`phylogeny/`) | `tree_overview`: monophyletic species clades collapsed to one tip "Species (k haplotypes, n records)"; non-monophyletic species left expanded and listed | `tree_by_genus.pdf`: subtree at each genus's most recent common ancestor; `tree.pdf/.svg` keeps every tip, height 0.14 in per tip, 6 pt labels, support shown when ≥ 0.7 |
| Distribution map (`geography/`) | by species (or haplotype, small datasets) | `distribution_map_by_species.pdf` (replaces the haplotype- and species-faceted maps) |
| Region abundance, relative and total (`extended/geography/`) | species × region | haplotypes × region, one page per species |
| Metadata field (each field) | records by species (stacked by value) | `<field>_by_haplotype.pdf`, one page per species; `<field>_by_region` (one figure) |
| Records by collection year | species × year heatmap (30 species with the most records) | stacked by haplotype, one page per species |
| Sampling timeline | first/last date per species | first/last date per haplotype, one page per species |
| Metadata coverage per haplotype | fields × species | fields × haplotypes, one page per species |

**Region facet** (replaces country facets). Metadata and timeline "by region" views use the
run's region column (`--geo-category`: `ocean_basin` with GOaS, or the custom shapefile's
category such as `freshwater_basin` or `biogeographic_realm`), the geography the user chose
for the run, defined for any shapefile. The caption gives the denominator ("1,373 of 7,201
assigned records have an ocean_basin"). When the run has no region analysis or fewer than
two regions with records, the view uses `country/ocean` and says so.

**Defaults.** Without `--extended`: tree (overview, by genus, full) and distribution map
(overview, by species). With `--extended`: everything above.

### 5. Report (Phase 12)

The report is rebuilt as `boldgenotyper/report/` (one module per section plus the page
shell and an `insights` module) and is generated **after** the output layout, from the
final run folder (tables, figure manifests) and the in-memory provenance. It no longer reads
staging files. `reports.py` keeps only the non-HTML helpers the pipeline uses
(`compute_assignment_summary`, `generate_assignment_summary`).

**Sections**

1. **Overview**: input, download date, key settings; counts (records, QC-passed, assigned,
   haplotypes, species-level taxa, regions); **Key findings**.
2. **Records and haplotypes**: status chart and counts; error-filter outcome
   (corrected, unassigned and why).
3. **Taxonomy and labels**: counts; "Needs attention": haplotypes not assigned at species
   level (with evidence and suggestion), label conflicts ranked by evidence, curated
   haplotypes, curation rows not applied.
4. **Phylogeny**: overview tree; genus dropdown; non-monophyletic species; excluded tips.
5. **Geography**: overview map; species dropdown; region bars; coordinate quality (records
   with coordinates, mapped, not mapped by `coord_status`, outside every region).
6. **Sampling and metadata**: field coverage chart; records by year and sampling timeline
   (view dropdown: species, haplotypes of one species, region); categorical fields (field
   and view dropdowns).
7. **Divergence** (`--extended`): label-based gap; species-pair summary.
8. **Methods**: as now, with correct values; methods statement filled in.
9. **Output files**: every file grouped by purpose (start here, tables, sequences, figures,
   extended), with what it holds and when to use it, generated from `run_readme.FILE_DOCS`
   so the report and README cannot disagree.

**Key findings** are a fixed list of observations, each shown only when it applies, with
counts and a link; none interprets biology:

- share of QC-passed records assigned; the largest exclusion status
- error singletons corrected and left unassigned (tied, none within the threshold)
- haplotypes not assigned at species level, and how many have a suggested taxon
- haplotypes with label conflicts and the records involved; haplotypes carrying more than
  one species label
- curated haplotypes; curation rows not applied
- suspect haplotypes and their reasons
- species not monophyletic in the tree
- records with coordinates, mapped, not mapped by reason; regions with records
- collection-year range and share of records with a date

**Tables**: up to 10 rows inline; longer tables show the top 10 by the stated order and
"N more in `<file>`" with the true count. Removed: the full haplotype taxonomy table, the
species composition table, the haplotype × region table, the field coverage table, the
first-sampled table, the full label-conflict list.

## Testing

- Unit tests for `taxon_evidence`, `taxon_curation`, figure paging (item caps, "Other",
  page per species, manifest), region-facet fallback, query output files, curated query
  calls, overlays with and without a tree, removed-flag errors.
- A second synthetic dataset with more than 40 haplotypes across several species and genera
  (generator in `tests/synthetic_data.py`) for the large-dataset paths, including a
  non-monophyletic species and a 4/4 label tie with BIN and distance evidence.
- Report tests read the generated HTML: no "not recorded", section order, insight counts
  equal to the run tables, truncation counts correct, every link resolves.
- Verification (scratch only): re-run the order-level and genus-level datasets and a query
  with metadata; check every figure page and the report by eye; compare all run tables with
  the Phase 7 runs (the changes affect presentation, not results, except curated taxa).

| Phase | Content |
|---|---|
| 8 | Correctness fixes, test failures, removals |
| 9 | Taxon evidence and curation |

## Risks

- **Scope.** Phases 11 and 12 are the largest. They change presentation only; the
  verification compares all run tables with the Phase 7 runs.
- **Evidence over-reach.** Suggestions could be read as calls. They are labeled
  "suggested", never applied, and the report shows the evidence beside them.
- **Curation drift.** A curation keyed by `seq_md5` matches only runs with the same core
  region; matching by sequence containment covers other datasets, and every unmatched row
  is reported.
- **Region facets on custom shapefiles** with many regions (e.g. hundreds of basins): the
  by-region view uses the same 12-item cap ("Other regions (n)").
